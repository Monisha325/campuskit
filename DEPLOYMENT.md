# Deploying CampusKit

## 1. Deploy the API on Render

1. Push this repository to GitHub.
2. In Render, select **New → Blueprint** and choose the repository.
3. Render discovers `render.yaml`. It creates the `campuskit-api` service with a persistent SQLite disk at `/var/data`.
4. Enter the production web URL as `CORS_ORIGIN` when Render prompts for it. For two Vercel deployments, use a comma-separated list.
5. After deployment, confirm `https://<your-api-domain>/health` returns `{ "status": "ok" }`.

`JWT_SECRET` is generated by Render and is never committed. The Blueprint intentionally uses the repository root because pnpm workspace packages live outside `server/`.

## 2. Deploy the booking app on Vercel

Create a Vercel project from the same repository. Keep its Root Directory as the repository root so it can build the workspace packages.

| Setting | Value |
| --- | --- |
| Framework Preset | Vite |
| Install Command | `corepack pnpm install --frozen-lockfile` |
| Build Command | `corepack pnpm --filter @campuskit/web build` *(builds shared tokens first)* |
| Output Directory | `apps/web/dist` |
| Environment Variable | `VITE_API_BASE_URL=https://<your-api-domain>` |

Redeploy the API after adding the web URL to `CORS_ORIGIN`.

## 3. Deploy the component showcase on Vercel

Create a second Vercel project from the same repository. Again, use the repository root.

| Setting | Value |
| --- | --- |
| Framework Preset | Vite |
| Install Command | `corepack pnpm install --frozen-lockfile` |
| Build Command | `corepack pnpm --filter @campuskit/docs build` *(builds shared tokens first)* |
| Output Directory | `apps/docs/dist` |

## 4. Verify the production release

1. Sign in through the web deployment with `student@test.edu` / `Test@1234`.
2. Submit a booking and verify it appears in My Bookings.
3. Sign in as `admin@test.edu` / `Test@1234` and approve it in Admin Queue.
4. Check the docs deployment at mobile width and switch between Bootstrap and Material themes.
